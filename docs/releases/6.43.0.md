New in XUnitAssured.Camunda: **`CamundaHubClient`**, a client of the Camunda Hub (the Web Modeler) REST API, for a tool that saves diagrams and forms in the Hub and reads them back. Upgrading from 6.42.0 requires no code changes.

- **Two API versions, one set of methods.** It speaks the Camunda Hub API v2 (`/api/v2`) and the Web Modeler API v1 (`/api/v1`, deprecated in Camunda 8.10 and removed in 8.12), with the names of the v2: workspace, project, folder, file, version. With no `ApiVersion` in `CamundaHubSettings`, the first call chooses, once: the v2 when `GET /api/v2/info` answers, the v1 when only `GET /api/v1/info` does, and a refusal 404 when neither does. A 401 or a 403 is the refusal of the credentials, not a reason to switch. `GetInfoAsync` says which one it speaks, and, on the v1, the permissions of the client.
- **OAuth only.** The Hub takes only a JWT, so `For` refuses any other `authentication.type`, and a missing client id, client secret or `oauthUrl`, naming the field and never the secret. The audience is `web-modeler-public-api` when empty. Nothing comes from the `CAMUNDA_*` environment variables: those are the credentials of the orchestration cluster.
- **Navigation.** `SearchWorkspacesAsync`, `CreateWorkspaceAsync`, `GetWorkspaceAsync` (with its projects), `SearchProjectsAsync`, `CreateProjectAsync`, `GetProjectContentAsync`, `GetFolderContentAsync` and `CreateFolderAsync`. On the v1, the workspace is its "project" and the project its "process application". The searches follow every page and keep only the exact name.
- **Files.** `SearchFilesAsync`, `GetFileAsync` (null when the Hub does not have it), `CreateFileAsync` (at the root of a project or in a folder) and `UpdateFileAsync` with the revision read. A stale revision is a `CamundaApiException` with `Status == 409` and the `detail` of the Hub. The type is `CamundaHubFileType.Bpmn` or `Form`; a file of another type, such as a DMN, comes with a null type.
- **Versions.** `CreateVersionAsync` (a snapshot of the current content), `SearchVersionsAsync` and `RestoreVersionAsync`.
- **Like `CamundaApiClient`:** one client per configuration, connections reused, a deadline per call (10 s by default), the token kept and asked once for concurrent calls and renewed once on a 401 or 403, the `observe` callback without the authorization header, and the same three exceptions.
