New in XUnitAssured.Camunda: **`CamundaApiClient`**, a public client of the Camunda 8.10 REST API on the official SDK, for a tool that drives a process instance itself (activating and completing jobs, reading the instance) instead of through the test DSL. The DSL now runs on the same client. The SDK goes to `Camunda.Orchestration.Sdk` 10.0.3. Upgrading from 6.36.1 requires no code changes.

- **One client per configuration, with its connections reused.** `CamundaApiClient.For(settings)` returns the same client for the same `camunda` settings for the life of the process, keyed by the address, the tenant and the authentication, with a hash of the password and of the secret, never the value. Underneath is one `HttpClient` on a `SocketsHttpHandler` that renews its connections every 5 minutes and closes the idle ones after 1. Before, a caller that built a client per call opened a connection per call, and a loop that polls the cluster left thousands in TIME_WAIT.
- **The operations a run needs**: the topology, the definitions (the latest of each process, or every version of one), the XML of a definition, the deployment of several resources, starting an instance, activating jobs (with the long wait and the job timeout), completing a job, throwing its BPMN error, failing it, giving it back with its retries, renewing its timeout, cancelling an instance, searching user tasks, assigning and completing one, searching instances (by parent, process, state and a variable), reading an instance, the open message subscriptions, correlating a message, the elements of an instance, the settled elements, and the incidents.
- **A deadline per call, from the cancellation token.** Each operation takes a `timeout`: 10 s by default, 30 s for a deployment, and the long wait plus 10 s for a job activation. A call past it throws `CamundaUnavailableException` with the deadline; a call the caller cancels throws `OperationCanceledException`, as before. The client's `HttpClient` has no timeout of its own.
- **Three exceptions say what went wrong.** `CamundaApiException` carries the status, the `title` and the `detail` of the problem document, and the path called. `CamundaCredentialException` says whether the identity provider refused the client (with its status and `error_description`, the secret replaced by `***`), answered without a token, or whether the Camunda refused the credentials. `CamundaUnavailableException` says who did not answer, and whether the deadline passed or the connection failed. A command on a job, an instance or a user task that no longer exists returns `false`, and reading an instance that is not in the search yet returns `null`.
- **The OAuth token is the client's.** It is asked by client credentials, with the audience and the new `scope` setting (`camunda.authentication.scope`, or `CAMUNDA_OAUTH_SCOPE`), kept until 30 s before it expires, asked once for concurrent calls, and renewed once when the Camunda refuses it. The SDK's own OAuth manager is not used: with the client's `HttpClient`, it asked for the token on a client of its own, outside the reused connection, and its refusal did not carry the provider's status. A settings section that names no type still means `Basic` with a username and `OAuth` with a client id, and what it leaves out still comes from the `CAMUNDA_*` variables.
- **Job commands are tried again when the Camunda does not answer.** Completing, throwing the error and failing a job go up to 3 times, 1 s apart; a job that no longer exists on a new attempt counts as the success of the earlier attempt, which reached the cluster without its answer coming back. A refusal is not tried again.
- **The settled elements.** `SearchSettledElementsAsync` searches the elements again, 500 ms apart and up to 20 times by default, while one is still `ACTIVE`, for an instance left completed or terminated: the search of the Camunda lags behind the engine. After the attempts it returns the last ones seen, without an error.
- **Each HTTP request is told to its caller.** Every operation takes an `observe` callback that hears a `CamundaCall` per request (the token request included): the method, the path, the status or the lack of one, the duration, and whether it went again with a renewed token. It never carries the authorization header, the token or the secret. Concurrent callers each hear only their own calls.
- **The test DSL runs on the client.** The steps get the same shared client by their settings, so the DSL and a tool in the same process share the connection and the token. The DSL's verbs, results and failures do not change.
- **Upgrade notes**: with OAuth, `camunda.authentication.oauthUrl` (or `CAMUNDA_OAUTH_URL`) is now required up front. With no REST address at all, the client uses `http://localhost:8080`, Camunda 8 Run's address.
