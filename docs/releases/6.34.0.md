New feature in XUnitAssured.Kafka: a consume can read only what the test produced on a topic with history. Upgrading from 6.33.0 requires no code changes; a consume without the new verbs behaves as before.

- **`FromTimestamp(DateTimeOffset)`** on `Consume()` starts every partition at the first message written at or after the moment, ignoring the group's committed offsets; a partition with nothing as new starts at its end. A consume used to start at the committed offset or at `AutoOffsetReset` and return the first message it found, which on a shared topic with history is an old message, not the one the test caused.
- **`WhereKey(string)`** on `Consume()` returns only a message with exactly this key, skipping the others until one arrives or the timeout ends.
- **`KafkaConsumeStep.ConsumeFrom` and `KeyFilter`** hold them, and every verb that rebuilds the step keeps them. Both apply to `Consume`, not to `ConsumeBatch`. The timestamps are the broker's (`CreateTime` by default, from the producer's clock).
- **The `Broker` tests also need Kafka** on `127.0.0.1:9092`: the non-blocking broker job starts `apache/kafka:4.3.1` next to RabbitMQ and runs a round trip on a topic with history.
